Modbus Gateway Multi-Master · Multi-Slave Router

A high-performance Modbus gateway written in Go. Supports arbitrary TCP / RTU / RTU-over-TCP protocol bridging, Slave ID-based routing across multiple downstreams, a built-in local virtual slave, and shared simulation models with data injection.

Download Binary Documentation

Architecture

Slave ID routing dispatches each request to the correct downstream. A mutex serializes requests per downstream connection, and local/injector downstreams can reference the same shared simulation model.

Full Protocol Support

TCP, RTU, and RTU-over-TCP on both upstream and downstream, mixed freely.

Slave ID Routing

Route requests to different downstreams by Slave ID. Supports ranges and lists.

Local Slave

Built-in virtual slave with memory, file, or mmap persistence; shareable via simulation.ref in v1.

Multi-Master Concurrency

Multiple masters; a mutex serializes requests per downstream connection.

RS485 Control

Full RTS timing control for industrial serial converters.

pprof Profiling

Optional pprof endpoint for CPU / heap / goroutine diagnostics.

Shared Simulations & Injection

Config v1 lets local/injector downstreams share one named model, with injector mapping writes into read-only tables.

Quick Start

1. Build

bash
git clone https://github.com/ffutop/modbus-gateway.git cd modbus-gateway go build -o modbus-gateway

2. Run

# Start with a config file
./modbus-gateway -config config.yaml

3. Or use Docker

# Multi-platform image: linux/amd64, linux/arm64
docker run -d --name modbus-gateway \   -v "$(pwd)/config.yaml:/etc/modbusgw/config.yaml:ro" \   -v "$(pwd)/data:/data" \   ffutop/modbus-gateway:latest

Configuration

All behavior is driven by config.yaml. See the Configuration Reference below.

# config schema v1: named, shareable simulation models
version: 1

simulations:
  - name: sim-device
    persistence:
      type: mmap
      path: "/data/sim-device.bin"

gateways:
  - name: "business-modbus"
    upstreams:
      - type: "tcp"
        tcp: { address: "0.0.0.0:502" }
    downstreams:
      - type: "local"
        slave_ids: "100"
        simulation: { ref: sim-device }

  # a second gateway injecting writes into the SAME model
  - name: "simulation-injection"
    upstreams:
      - type: "tcp"
        tcp: { address: "0.0.0.0:503" }
    downstreams:
      - type: "injector"
        slave_ids: "247"
        simulation:
          ref: sim-device
          mappings:
            - source: { table: coils, start_address: 0, count: 256 }
              target: { table: discrete_inputs, start_address: 0 }

log:
  level: "info"
  file: ""

Configuration Reference

Complete field reference for config.yaml, covering both the legacy (v0) and shared-simulation (v1) schemas.

version & simulations[]

An omitted version or version: 0 keeps the legacy per-downstream model. version: 1 enables shared simulations[] referenced via simulation.ref, and strictly rejects unknown fields.

Field Type Description
versionintConfig schema version (0 or 1); omitted = 0. Not the software release version.
simulations[].namestringNonempty, unique model name, referenced via simulation.ref.
simulations[].persistence.typememory · file · mmapStorage backend; empty/unknown falls back to memory. sql is not directly usable yet (no driver registered).
simulations[].persistence.pathstringFile path for file/mmap types — must name a file, not a directory.

pprof

Enables Go's built-in pprof HTTP server for runtime diagnostics.

Field Type Default Description
pprof.enabledboolfalseSet true to start the pprof HTTP server.
pprof.addressstringlocalhost:6060Listening address for the pprof server.

gateways[]

Array of independent gateway instances. Each runs its own upstream listeners, routing logic, and downstream connections.

Field Type Description
namestringHuman-readable label for logs.
upstreamsarrayList of master-side listeners.
downstreamsarrayList of slave-side targets with routing rules.

upstreams[]

Each entry defines one listener. Multiple upstreams share the same downstream pool.

Field Value / Type Description
typetcp · rtu · rtu-over-tcpProtocol the master uses to connect.
tcp.addressstringListen address for tcp / rtu-over-tcp.
serial.*see SerialSerial port settings for rtu type.

downstreams[]

Each entry defines one slave target via slave_ids. In v1, each local/injector entry must resolve to exactly one ID in 1-247.

Field Value / Type Description
typetcp · rtu · rtu-over-tcp · local · injectorSlave connection type. local = built-in virtual slave; injector = write-mapping into a shared model.
slave_idsstringRouting rule. Formats: "1" · "1,2,3" · "1-10". IDs must not repeat within a gateway.
tcp.addressstringRemote address for tcp / rtu-over-tcp.
serial.*see SerialSerial port settings for rtu type.
simulation.ref (v1)stringName of the simulations[] model this local/injector downstream binds to.
simulation.mappings[] (v1, injector only)arrayAt least one mapping; not declared for local. See Mappings below.
local.persistence.* (v0 legacy)memory · file · mmapLegacy (v0) inline persistence for an independent model; rejected under version: 1.

simulation.mappings[] (injector downstreams only, v1)

Accepts only FC05/06/15/16, mapping coils → discrete_inputs or holding_registers → input_registers without touching the source table.

Field Type Description
source.tablecoils · holding_registersTable the incoming write targets.
source.start_address / countuint1616-bit address range; start + count must not exceed 65536.
target.tablediscrete_inputs · input_registersRead-only table the write is mirrored into.
target.start_addressuint16Target address = target.start_address + request address - source.start_address.

serial fields (used in rtu upstreams & downstreams)

Field Default Description
device—Serial device path.
baud_rate—Baud rate.
data_bits8Data bits.
parityN"N" · "E" · "O"
stop_bits1Stop bits.
timeout500msRead timeout per request.

Timeouts & Limits (not YAML-configurable)

These are fixed in code, not YAML fields.

Item Behavior
TCP / RTU-over-TCP downstreamConnection and interaction timeout fixed at 10 seconds.
Gateway dispatch2-second context; not a reliable end-to-end latency guarantee.
RTU downstream idleCloses after 60 seconds idle and reopens on demand.
Local table sizeEach of the four tables has 65536 addresses (0-65535).

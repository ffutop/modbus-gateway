ONE CORE. MANY CONNECTIONS.

协议可以不同。路由保持清楚。

TCP、RTU 与 RTU-over-TCP 任意桥接。按 Slave ID 分发到真实设备或共享仿真模型。

一个进程运行多个网关；每个下游连接独立串行化请求。local 与 injector 可引用同一个 Simulation。

BUILT FOR MODBUS

把现场连接，交给同一个内核。

01

全协议支持

上游与下游均支持 TCP、RTU、RTU-over-TCP，可任意组合。

02

Slave ID 路由

按 Slave ID 将请求路由到不同下游，支持单值、范围（1-10）和逗号分隔列表。

03

本地虚拟从站

内置虚拟 Modbus 从站（支持 FC01-06、FC15、FC16），可插拔持久化：内存、文件或 mmap。在 v1 配置中可通过 simulation.ref 在多个下游甚至多个网关间共享同一模型。

04

多主并发

多主站同时连接；每个下游连接对象通过互斥锁串行化请求，防止 RS485 总线冲突。

05

RS485 控制

完整的 RTS 信号时序控制，可配置延迟，适配各类工业串口转接器。

06

pprof 性能分析

可选的 Go pprof HTTP 端点，通过 go tool pprof 进行 CPU、堆内存、Goroutine 诊断。

07

共享仿真与数据注入

v1 配置：在 simulations[] 下声明具名模型，多个 local / injector 下游可通过 simulation.ref 引用同一模型。injector 下游将写请求（FC05/06/15/16）从 coils / holding registers 映射到 discrete inputs / input registers，且不修改源表。

08

Docker 支持

多平台镜像（linux/amd64、linux/arm64）以 ffutop/modbus-gateway 名义发布到 Docker Hub，并按发行版本打标签。

CLI / DOCKER

快速开始

需要在服务器上部署？桌面端和命令行版共用配置；选择适合你的运行方式。

构建与运行

源码构建要求 Go 1.24.3+。也可以直接下载预构建的 CLI。

git clone https://github.com/ffutop/modbus-gateway.git
cd modbus-gateway
go build -o modbus-gateway .
./modbus-gateway -config config.yaml

Docker 部署

docker run -d --name modbus-gateway \
  -v "$(pwd)/config.yaml:/etc/modbusgw/config.yaml:ro" \
  -v "$(pwd)/data:/data" \
  ffutop/modbus-gateway:latest

一份 YAML，驱动全部行为

具名 Simulation 可由多个 local / injector 下游共享。保留原有 YAML 工作流，或在桌面端进行可视化编辑。

# config schema v1: named, shareable simulation models
version: 1

simulations:
  - name: sim-device
    persistence:
      type: mmap
      path: "/data/sim-device.bin"

gateways:
  - name: "business-modbus"
    upstreams:
      - type: "tcp"
        tcp: { address: "0.0.0.0:502" }
    downstreams:
      - type: "local"
        slave_ids: "100"
        simulation: { ref: sim-device }

  # a second gateway injecting writes into the SAME model
  - name: "simulation-injection"
    upstreams:
      - type: "tcp"
        tcp: { address: "0.0.0.0:503" }
    downstreams:
      - type: "injector"
        slave_ids: "247"
        simulation:
          ref: sim-device
          mappings:
            - source: { table: coils, start_address: 0, count: 256 }
              target: { table: discrete_inputs, start_address: 0 }

log:
  level: "info"
  file: ""

CONFIGURATION / YAML

配置参考

v0 配置保持兼容；v1 使用命名共享模型，拒绝未知字段。配置模式版本与软件发布版本无关。

version & simulations[]+

省略 version 或 version: 0 保留旧版结构，每个 local 下游在自己的 local.persistence 块中拥有独立模型；不能包含 simulations、simulation 或 injector。version: 1 会严格拒绝未知字段，将持久化配置移至顶层 simulations[]，并让 local / injector 下游通过名称引用模型。

字段 类型 说明
versionint配置模式版本（0 或 1）——并非软件发布版本号。省略时为 0。
simulations[].namestring非空且唯一的模型名称，供下游通过 simulation.ref 引用。
simulations[].persistence.typememory · file · mmap存储后端。为空或未知类型时回退为 memory。sql 虽被配置接受，但当前版本未注册驱动，暂不可直接使用。
simulations[].persistence.pathstringfile / mmap 类型的文件路径；必须指向文件而非目录，父目录须存在且可写。
pprof+

启用 Go 内置 pprof HTTP 服务器，用于运行时诊断。

字段 类型 Default 说明
pprof.enabledboolfalse设为 true 以启动 pprof HTTP 服务器。
pprof.addressstringlocalhost:6060pprof 服务器监听地址。
gateways[]+

独立网关实例数组，每个实例有自己的上游监听器、路由逻辑和下游连接。

字段 类型 说明
namestring日志中使用的可读标签。
upstreamsarray主站侧监听器列表（见下方 Upstream 字段）。
downstreamsarray带路由规则的从站侧目标列表（见下方 Downstream 字段）。
upstreams[]+

每个条目定义一个监听器，多个上游共享同一组下游。

字段 Value / Type 说明
typetcp · rtu · rtu-over-tcp主站连接使用的协议。
tcp.addressstringtcp / rtu-over-tcp 类型的监听地址（如 0.0.0.0:502）。
serial.*see Serialrtu 类型的串口参数（与下游 serial 字段相同）。
downstreams[]+

每个条目定义一个从站目标，slave_ids 控制哪些 Slave ID 被路由到此；仅当只有一个下游且 slave_ids 为空时才会创建默认路由。在 v1 中，每个 local / injector 条目必须恰好解析出一个 1-247 范围内的 ID —— 如需暴露多个 ID，请配置多个引用同一模型的条目。

字段 Value / Type 说明
typetcp · rtu · rtu-over-tcp · local · injector从站连接类型。local 为内置虚拟从站；injector 将外部写请求映射进共享模型，且不修改其源表。
slave_idsstring路由规则。格式："1" · "1,2,3" · "1-10"。同一网关内 ID 不可重复。
tcp.addressstringtcp / rtu-over-tcp 类型的远端地址（如 192.168.1.100:502）。
serial.*see Serialrtu 类型的串口参数。
simulation.ref (v1)string该 local / injector 下游绑定的 simulations[] 模型名称，须与已声明的条目匹配。
simulation.mappings[] (v1, injector only)array至少一个映射；local 类型不声明此字段。详见下方 Mappings 说明。
local.persistence.* (v0 legacy)memory · file · mmap旧版（version 0）内联持久化配置，用于 local 下游自身的独立模型。在 version: 1 下会被拒绝 —— 请改用 simulations[] + simulation.ref。
simulation.mappings[] (injector downstreams only, v1)+

injector 仅接受 FC05/FC06/FC15/FC16，并将每次写入映射到共享模型的 coils→discrete_inputs 或 holding_registers→input_registers 表，且不修改源表。每次写入必须完全落在一个映射范围内；同一 injector 内同表的源区间不可重叠，同一共享模型内同表的目标区间也不可跨网关重叠。

字段 类型 说明
source.tablecoils · holding_registers传入写请求所针对的表。
source.start_address / countuint1616 位地址区间；start + count 不得超过 65536。
target.tablediscrete_inputs · input_registers写入被映射到的只读表。
target.start_addressuint16目标地址 = target.start_address + 请求地址 - source.start_address；数量沿用源区间的 count。
serial fields (used in rtu upstreams & downstreams)+
字段 Default 说明
device—串口设备路径（如 /dev/ttyUSB0）。
baud_rate—波特率（如 9600、19200、115200）。
data_bits8数据位（7 或 8）。
parityN"N"（无）· "E"（偶）· "O"（奇）。
stop_bits1停止位（1 或 2）。
timeout500ms每次请求的读取超时（如 500ms、1s）。
rqst_pause100ms解析为时长；省略或 0 时取 100ms。当前 RTU 传输层暂未使用该字段。
rs485false启用 RS485 RTS 信号控制。
delay_rts_before_send0发送前 RTS 置位延迟（如 2ms）。
delay_rts_after_send0发送后 RTS 取消延迟。
rts_high_during_sendfalse发送期间保持 RTS 高电平。
rts_high_after_sendfalse发送完成后保持 RTS 高电平。
rx_during_txfalse允许在发送期间同时接收。
log+
字段 Default 说明
log.levelinfo"debug" · "info" · "warn" · "error"
log.file""为空或 "-" 时输出到 stdout；否则以追加方式写入指定文件（不会自动创建父目录）。
超时与限制（不可通过 YAML 配置）+

以下限制固化在代码中，并非 YAML 字段。

Item 行为
TCP / RTU-over-TCP downstream连接与交互超时固定为 10 秒。
Gateway dispatch2 秒调度上下文，并非可靠的端到端限制：锁等待、网络 I/O 和串口行为仍会影响实际时延。
RTU downstream idle空闲 60 秒后关闭，按需重新打开。
Local table size四张表各有 65536 个地址（0-65535）；新模型初始值均为 0。
异常响应码+
条件 响应
不支持的 local / injector 功能码0x01
local 地址越界、未映射的注入或跨边界写入0x02
部分 local 请求长度 / 数量校验失败0x03
TCP / RTU-over-TCP 处理错误，含无路由0x04
上下文超时 / 请求超时（并非所有网络超时都会映射到此码）0x0B
RTU 处理错误记录错误但不发送响应，主站通常会超时。

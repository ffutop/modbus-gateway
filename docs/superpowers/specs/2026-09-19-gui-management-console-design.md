## 1. 要解决的问题

现场工程师排障时只能看日志、手写 `config.yaml`，有两件事做不好：

1. **看不到运行状态。** 路由命中、请求量、错误、延迟、模拟从站的寄存器值，都没有结构化视图。
2. **配置错误发现得太晚。** v1 配置层级深（`simulations` / `injector` / `mappings`），Slave ID 冲突、映射重叠只有在重启时才暴露。

因此控制台只做两件事：**查看运行状态**，以及**编辑配置、保存前校验**。同一套界面以两种形态交付：

- **Web 版：** 服务端二进制内嵌的控制台，用浏览器访问；
- **桌面版：** 面向 Windows、Linux、macOS 的安装包，双击即可使用。

## 2. 约束

| 约束 | 来源 | 推论 |
|---|---|---|
| 服务端二进制保持单文件、纯 Go、可无头部署 | 现有交付方式；边缘设备常无显示器 | 桌面版的任何依赖都不能进入服务端构建；控制台在服务端是可关闭的旁路 |
| 网关内核只有一份 | 测试与维护成本 | 桌面版直接运行服务端二进制，而不是另编一个内核 |
| 工业现场常离线 | 部署环境 | 前端不依赖 CDN 和在线字体；桌面版安装包可离线安装，不要求另装运行时 |
| `config.yaml` 是权威产物，会被人手工编辑并纳入 git | `modbus-gateway.md` 的产品立场 | GUI 写回不能破坏注释、顺序和格式；不能覆盖他人在文本编辑器里的修改 |
| 关闭控制台时行为与今天完全一致 | 存量部署 | 服务端未配置 `ui` 时不初始化任何管理面组件 |

**非目标：** 配置热加载、多用户与权限、管理远程网关（需要先有认证和 TLS）、改变转发或路由语义、触摸屏和深色模式。

## 3. 技术路线

- **Web 版：** 前端静态资源用 `go:embed` 编进服务端二进制，后端提供 REST + SSE。
- **桌面版：** 用 **Electron 外壳 + 服务端二进制子进程**。Electron 在后台启动随包附带的服务端二进制，开启管理面，再让窗口加载这个本机地址。窗口里加载的页面就是 Web 版的同一套前端。

桌面外壳选型：

| 方案 | 不选的原因 |
|---|---|
| Wails（Go + 系统 WebView） | macOS/Linux 需要 CGO，三个系统都必须原生构建；Windows 依赖 WebView2，离线或 LTSC 工控机需要另装；Linux 有 webkit2gtk 4.0/4.1 的版本碎片；SSE 能否通过 Wails 的请求通道需要先验证；还要把 `main.go` 拆成可复用的内核包 |
| Tauri | 需要引入 Rust 工具链 |
| 后台起服务，再用浏览器 `--app` 模式开窗口 | 依赖本机已装 Chrome 或 Edge；限制不了窗口最小尺寸，也没有原生菜单和文件对话框 |

**选择 Electron 的理由：** Go 代码只需要加几个启动参数；服务端产物原样复用，不需要 CGO；自带 Chromium，三个系统渲染一致，也不依赖系统里装了什么；打包、签名、公证、单实例、原生菜单都有成熟的现成方案。

**接受的代价：** 安装包约 90–120 MB，内存占用约 150–300 MB；需要新增 Node 工具链，并跟进 Chromium 的安全更新。桌面版面向工程师电脑和带显示器的工控机，可以接受这些代价；资源紧张的设备用服务端二进制。

**不支持的系统：** 新版 Electron 已不支持 Win7/8。这类机器使用"服务端二进制 + 浏览器"。

## 4. 架构

```
服务端二进制 modbus-gateway（纯 Go，Web 版和桌面版共用）
├── 现有内核：internal/gateway, config, simulation, local-slave, transport
├── internal/telemetry   新增：请求打点、计数器、环形缓冲
├── internal/api         新增：管理面 REST + SSE
└── web/ (go:embed)      新增：前端，原生 JS + 手写 CSS，无构建工具链

desktop/（Electron，只在打包桌面版时构建）
├── main.js     启动并监管子进程；窗口、菜单、对话框、单实例
├── preload.js  通过 contextBridge 暴露少量桌面能力给前端
└── resources/  随包附带对应平台的 modbus-gateway 二进制
```

现有代码已经具备的支撑：
- `simulation.Simulation` 已提供 `Status()`、`Version()`；`model.DataModel` 已提供四张表的加锁只读方法。
- `transport.SourceAddr(ctx)` 可以取到请求的来源地址。
- `config.Validate()` 可以直接复用为校验入口。

需要新增的：
- `handleRequest` 的埋点：目前没有任何计数和日志。
- 保留注释的配置写回：当前用 viper 加载，viper 不能写回，需要改用 `yaml.v3` 的 `yaml.Node`，见 5.3。
- 子进程模式所需的启动参数和退出方式，见 6.1。

## 5. 后端设计

### 5.1 管理面 API

| 方法 & 路径 | 用途 |
|---|---|
| `GET /api/v1/status` | 进程信息（版本、启动时间、配置文件路径）；每个模拟从站的 `status` 和 `version` |
| `GET /api/v1/metrics` | 按网关、按下游统计的累计请求数、错误数，近期 req/s，p50/p99 |
| `GET /api/v1/events`（SSE） | 请求日志流，按批推送（见 5.2） |
| `GET /api/v1/simulations/{name}/registers?table=&start=&count=` | 某张表一段地址的只读快照 |
| `GET /api/v1/config` | 磁盘上的配置文件（结构化 JSON），附带文件修订号，以及"与运行中配置是否一致" |
| `POST /api/v1/config/validate` | 校验草稿，不落盘 |
| `PUT /api/v1/config` | 携带修订号写回配置文件；响应提示"需重启生效" |

原则：只读端点直接读运行中的内部状态；写端点只写文件，不触碰运行中的网关。

### 5.2 遥测

- 每个请求记录：网关、下游、Slave ID、功能码、地址范围、来源地址、耗时、结果。
- 计数器使用原子操作，打点不得阻塞转发路径。
- 每个网关一个有界环形缓冲，默认 1000 条，纯内存，重启后清空。它是调试数据，不是审计数据；审计由注入路径的审计日志负责。
- p50/p99 在读取时从环形缓冲样本计算，不需要维护直方图。
- SSE 每 250ms 推一批新记录。前端只显示装得下的最新几行，所以高并发时允许丢弃中间记录。

### 5.3 配置读写

- **读取：** `GET /config` 返回**磁盘文件**的内容（即下次启动会生效的配置），同时返回 `running_matches: bool`，供界面提示"已保存但未重启"。
- **防覆盖：** 读取时返回文件修订号（内容哈希），`PUT` 必须带上；文件已被他人改过时返回 `409`。
- **保留格式：** 写回时在 `yaml.Node` 上做最小修改，保留注释、键顺序和缩进。不允许把规范化后的 `Config` 重新序列化覆盖整个文件。
- **只支持编辑 v1 配置：** v0 配置在 GUI 中只读，并提示手动迁移。v0 的 `local` 下游会被隐式合成模拟从站，无法无损写回。
- **校验：** `validate` 和 `PUT` 都复用 `config.Validate()`，返回能定位到具体对象和字段的错误列表。
- **重启：** 服务端进程不能可靠地自己重启自己，因此 API 不提供重启接口。桌面版的重启由 Electron 完成，见 6.2；Web 版由 systemd、Docker 或人工重启。

### 5.4 启用与访问控制

服务端（Web 版）在配置文件中启用：

```yaml
ui:
  enabled: false            # 默认关闭；未配置等同 false
  listen: "127.0.0.1:8090"  # 默认只监听本机
```

- **默认关闭**，以满足"关闭时行为不变"的约束。
- 默认只监听回环地址。需要远程访问时，用户显式填写监听地址，并且应当绑定面向运维网段的网卡，不能暴露在直连现场设备的网口上。管理面端口必须与所有 Modbus 监听端口不同。
- 网关本身不实现 TLS 和账号体系。远程访问的安全由部署层负责：防火墙白名单，或者反向代理做 TLS 和基础认证。

桌面版通过启动参数启用，并且必须加 token，见 6.1。

## 6. 桌面版

### 6.1 子进程协议（Go 侧改动）

服务端二进制新增以下启动方式，供 Electron 使用；Web 版和服务端部署不受影响。

| 参数 / 环境变量 | 作用 |
|---|---|
| `-ui-listen 127.0.0.1:0` | 开启管理面，覆盖配置文件中的 `ui` 段。端口 `0` 表示由系统分配 |
| 环境变量 `MODMUX_UI_TOKEN` | 设置后，所有 API 请求都必须携带该 token，否则返回 `401`。token 放在环境变量里而不是命令行参数里，因为命令行参数会被本机其他用户通过进程列表看到 |
| `-exit-on-stdin-eof` | 标准输入关闭时走优雅关闭流程 |

- **就绪信号：** 管理面开始监听后，向 stdout 输出一行 JSON，例如 `{"event":"ui_ready","addr":"127.0.0.1:53121"}`。由 Go 绑定端口再上报实际地址，避免 Electron 先挑一个空闲端口、再被别的程序抢占。
- **为什么用 stdin 关闭来退出：** 在 Windows 上，Electron 的 `child.kill()` 等同于强制终止进程，Go 来不及刷写 mmap 等持久化数据。改为 Electron 退出时关闭子进程的 stdin，Go 检测到 EOF 后执行与 `SIGTERM` 相同的关闭流程。Electron 崩溃时管道也会断开，子进程同样会退出，不会留下孤儿进程。
- **Host 校验：** 携带 token 的管理面只接受 `Host` 为回环地址的请求，以防 DNS 重绑定攻击。

### 6.2 Electron 外壳的行为

| 行为 | 规定 |
|---|---|
| 启动 | 选定配置文件后启动子进程，等待就绪信号（超时 10 秒）后加载 `http://<addr>/`。启动失败时显示子进程最后几行输出和退出码，例如端口被占用、串口打不开 |
| token | 每次启动生成随机 token；由主进程通过 `session.webRequest` 自动加到每个请求上，页面 JS 不接触 token |
| 配置文件 | 通过原生文件对话框打开，记住最近打开的文件。首次启动时在系统的用户配置目录下生成示例配置 |
| 重启 | 工具栏和菜单提供「重启网关」：Electron 先关闭子进程的 stdin，等子进程退出后用同一个配置文件重新启动。界面上"保存后需重启生效"的提示里，在桌面版直接给出这个按钮 |
| 子进程意外退出 | 窗口提示"网关已停止"，显示退出码和最后几行输出，提供"重新启动"按钮；不自动循环重启 |
| 网关输出 | 子进程的 stdout 和 stderr 接到底部面板的「网关输出」标签页，只有桌面版有这个标签页 |
| 窗口 | 由 `BrowserWindow` 强制最小尺寸 1280×720；提供原生菜单：文件（打开配置、最近打开、保存、退出）、编辑、视图、帮助 |
| 单实例 | 用 `requestSingleInstanceLock` 保证只有一个实例，防止两个实例抢同一个 Modbus 端口或串口；再次启动时聚焦已有窗口 |
| 关闭窗口 | 关闭窗口即停止转发；网关运行中时先弹窗确认。最小化到托盘、后台继续转发不在本期 |
| 安全基线 | `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；只允许加载子进程地址；外部链接用系统浏览器打开 |

生产环境长期运行建议仍然使用服务端二进制，配合 Windows 服务、systemd 或 Docker。桌面版定位于调试、配置和小规模运行。

### 6.3 前端如何区分两种形态

前端是同一套代码。`preload.js` 通过 `contextBridge` 暴露 `window.modmuxDesktop`，其中只有：打开文件对话框、最近文件、重启网关、订阅网关输出、应用版本。前端检测到这个对象存在，就显示桌面版独有的元素：「重启网关」按钮、「网关输出」标签页、菜单快捷键；检测不到，就显示 Web 版的最小尺寸提示遮罩。

## 7. 界面设计

依据桌面端原型评审（2026-10-03）确定，Web 版和桌面版共用。

### 7.1 原则

- **一屏完成，不滚动，不翻页。** 应用根容器固定为窗口大小；任何内容都不出现页面级滚动条。
- **选中对象是唯一的上下文。** 在资源树或拓扑图里选中一个对象，编辑区、检查器、日志筛选、拓扑高亮都随之切换。

### 7.2 布局：工作台

| 区域 | 位置 | 内容 |
|---|---|---|
| 顶栏 | 顶部 | 配置文件名（有未保存修改时标 `•`）；校验、保存；未保存修改数和"保存后需重启生效"（桌面版附「重启网关」）；配置与运行中是否一致；暂停实时数据 |
| 资源树 | 左侧 | 网关 → 上游 / 下游；模拟从站；系统设置。节点上标出 req/s、Slave ID、校验错误、未保存修改 |
| 编辑区 | 中间 | **详情**：属性表单、路由表或映射表、寄存器查看器。**拓扑**：见 7.3 |
| 检查器 | 右侧 | 选中对象的 req/s、错误率、p50/p99、近期趋势（前端累积 `/metrics` 采样得到） |
| 底部面板 | 编辑区和检查器下方 | 请求日志（按选中对象筛选）/ 问题（校验结果）/ 网关输出（仅桌面版） |

菜单由桌面版的原生菜单提供，页面内不画菜单栏和窗口按钮。上游的"当前连接"列表没有数据来源（transport 层不跟踪连接），不进入实现。

### 7.3 拓扑视图

- 展示选中对象所在网关的结构：上游 → 网关 → 下游 → 模拟从站。网关没有引用模拟从站时，只显示前三列；选中的是模拟从站时，展示引用它的网关。
- 连线上标注实时 req/s；`injector` 的注入写入用不同颜色区分。选中节点及其连线高亮，节点上直接标出校验错误。
- 只用于查看和导航：点击节点等同于在资源树里选中它，不在图上编辑。

### 7.4 不滚动的实现规则

| 内容 | 规则 |
|---|---|
| 请求日志、问题列表、网关输出 | 按面板可用高度计算行数，只显示最新的 N 条 |
| 寄存器查看器 | 按宽度选列数（8 / 10 / 16，位表最多 32），按高度选行数；用"地址跳转 + 整屏步进"代替滚动 |
| 日志表的列 | 宽度不足时依次隐藏：来源 → 网关 → 地址和下游。时间、从站、功能码、耗时、结果始终保留 |
| 资源树 | 放不下时自动折叠不含选中项的网关，并提示已折叠几个 |
| 窄窗格中的工具条 | 允许换行，不允许横向溢出 |

### 7.5 窗口尺寸

**最小 1280 × 720**，即工控机常见的 1366 × 768 屏幕扣除任务栏后的可用区域。桌面版由窗口强制；Web 版在浏览器窗口小于这个尺寸时显示提示遮罩。

| 宽度 | 布局 |
|---|---|
| 1280–1919 | 编辑区用标签页切换「详情」和「拓扑」；1600 以上侧栏和检查器适当加宽 |
| 1920–2559 | 「详情」和「拓扑」左右并排常驻 |
| ≥ 2560 | 请求日志从底部面板移到最右侧整列，编辑区获得全部高度 |

高度方向：底部面板高度为 `clamp(180px, 32vh, 420px)`；窗口高度 ≥ 1000 时，检查器追加「最近错误」列表。侧栏宽度和底部面板高度可以拖动调整，双击恢复默认。

### 7.6 字号与字体

| 用途 | 尺寸 |
|---|---|
| 正文 | **14px** |
| 小字（表头、分组标题、徽标） | 12px |
| 等宽数字（地址、寄存器值、耗时） | 13px |
| 页面标题 / 指标大数字 | 18px / 20px |
| 表格行高 / 输入框和按钮高度 | 27px / 29px |

所有尺寸由一个以正文字号为基准的系数推导，日后可以据此提供 16px 大字号选项，本期不做。字体使用系统字体栈（`Segoe UI` / `-apple-system` / `PingFang SC` / `Microsoft YaHei UI`，等宽字体用 `Cascadia Mono` / `SF Mono` / `Consolas`），不下载 Web 字体。

### 7.7 快捷键

两种形态都可用：保存 `Ctrl/⌘+S`；暂停实时数据 `Space`（焦点在输入框时不生效）。切换「详情 / 拓扑」的 `Ctrl/⌘+1/2` 只在桌面版通过原生菜单提供，因为在浏览器里这组按键会被标签页切换占用。

## 8. 发行与打包

| 发行物 | 平台 | 形式 |
|---|---|---|
| 服务端二进制（现有） | linux / windows / darwin × amd64 / arm64 | `.tar.gz` / `.zip` |
| Docker 镜像（现有） | linux/amd64、linux/arm64 | `ffutop/modbus-gateway` |
| **桌面版（新增）** | Windows x64 / ARM64 | NSIS 安装包，另附免安装版 |
| | macOS arm64 / x64 | 按架构分别提供 `.dmg` |
| | Linux x64 / arm64 | AppImage、`.deb` |

- **构建：** 用 `electron-builder` 打包。桌面版直接使用现有构建任务产出的对应平台服务端二进制，放进安装包的 `resources/`。打包任务依赖现有的 Go 构建任务，在 `windows-latest`、`macos-latest`、`ubuntu-latest`（x64）和 Ubuntu arm64 runner 上分别执行。现有的 Go 构建任务和 Docker 构建任务不变。
- **版本：** 桌面版和服务端二进制使用同一个 tag 和版本号，在同一个 GitHub Release 中发布。
- **签名：** 不购买代码签名证书，桌面版以未签名形式发布。macOS 版只做 ad-hoc 签名（Apple Silicon 上程序必须带签名才能运行，ad-hoc 签名不需要证书）。由此带来的安装拦截由用户自行放行，README 和 Release 说明中给出各系统的放行步骤：
  - **Windows：** SmartScreen 提示时，点「更多信息 → 仍要运行」。
  - **macOS：** 在「系统设置 → 隐私与安全性」中点「仍要打开」；如果提示"已损坏，无法打开"，执行 `xattr -dr com.apple.quarantine /Applications/<应用名>.app` 去掉隔离标记。
  - **Linux：** 没有拦截。AppImage 需要先 `chmod +x`。
- **离线：** 安装包包含全部运行时，安装和运行都不需要联网。本期不做自动更新。

## 9. v0.6.0 验收标准

**通用**
1. 服务端未配置 `ui` 或 `ui.enabled: false` 时，行为与 v0.5.0 完全一致，不新增任何监听端口；服务端构建不引入 CGO 和任何桌面依赖。
2. 开启管理面后，`/status`、`/metrics`、`/events` 返回运行时真实数据；寄存器查看器的值与用 Modbus 客户端读取同一模拟从站的结果一致。
3. 提交非法配置（Slave ID 冲突、映射越界等）时，`validate` 和 `PUT` 都拒绝并返回定位到对象的错误，不落盘。
4. 通过 GUI 保存后，文件中原有的注释和键顺序保持不变；读取配置之后，如果文件被文本编辑器修改过，`PUT` 返回 `409`，不覆盖文件。v0 配置可以查看，但不能保存。
5. 窗口尺寸在 1280 × 720 到 2560 × 1440 之间时，没有页面级滚动，面板内容不被截断或横向溢出，布局按 7.5 切换。
6. 选中一个对象后，编辑区、检查器、日志筛选、拓扑高亮指向同一个对象。
7. 高负载转发时，开启管理面带来的转发延迟增量可忽略（门限在压测后给出）。

**Web 版**

8. 默认配置下，管理面只能从本机访问。

**桌面版**

9. 在全新安装、未联网的 Windows 10/11 x64、macOS（arm64 与 x64）、Ubuntu 22.04/24.04 x64、Ubuntu 24.04 arm64 上，按 README 中的放行步骤操作后可以直接运行，不需要另装任何运行时。
10. 子进程的管理端口不接受其他主机的连接；本机请求不带 token 时返回 `401`。
11. 关闭窗口后，子进程走优雅关闭流程，mmap 持久化的数据完整；强制结束 Electron 进程后，子进程在 5 秒内退出。
12. 保存配置并点击「重启网关」后，新配置生效。
13. 第二次启动只会聚焦已有窗口，不会启动第二个子进程。
14. 在三个系统上都能用 RTU 串口上下游完成读写。

## 10. 待确认

| 项 | 说明 |
|---|---|
| 未签名应用在 macOS 上的放行 | 需要实测：通过 Gatekeeper 放行 `.app` 后，它启动 `resources/` 里附带的 Go 二进制时，会不会被再次拦截 |
| Ubuntu 新版本上的 Electron 沙箱 | Ubuntu 23.10 起限制非特权用户命名空间，Electron 的沙箱可能因此无法启动，AppImage 受影响最明显。需要在 Ubuntu 24.04 x64 和 arm64 上实测，必要时随 `.deb` 附带 AppArmor 配置 |
| Electron 版本跟进策略 | Chromium 有安全更新时，桌面版需要发补丁版本；需要约定跟进节奏 |
| 环形缓冲容量与打点开销 | 默认 1000 条是估计值，需要压测确认，并给出第 9 节第 7 条的门限 |
| 资源规模上限 | 网关数量多到每个只占一行也放不下时，资源树仍会溢出。需要确定上限，或者给资源树加过滤框 |
| `yaml.Node` 最小修改的覆盖范围 | 修改字段、增删列表项（下游、映射）都要保留相邻注释，需要逐一验证 |

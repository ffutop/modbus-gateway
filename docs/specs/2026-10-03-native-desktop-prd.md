# ModMux 原生桌面版 — 产品需求文档

**日期：** 2026-10-03 起草（当时为浏览器控制台＋Electron 方案）；2026-10-04 改为 Gio 原生桌面；2026-10-06 按 v0.6.2 实现倒推重写
**状态：** 已实现（v0.6.x 预览版）
**依据：** 本文描述代码的实际行为与已记录的取舍，不描述未实现的设想。功能细节见 [桌面使用说明](../../desktop-native/README.md)，模块职责与验证入口见 [架构与验证](../../desktop-native/DEVELOPMENT.md)；被管理的模拟模型见 [共享模拟模型 PRD](2026-09-19-shared-simulation-injection-prd.md)。

---

## 1. 问题

现场工程师排障时只有日志和手写的 `config.yaml`，有两件事做不好：

1. **看不到运行状态。** 请求打到了哪条链路、是否成功、耗时多少、模拟从站的寄存器现在是什么值，都没有结构化视图。
2. **配置错误发现得太晚。** v1 配置层级深（`simulations` / `injector` / `mappings`），Slave ID 冲突、映射重叠、引用缺失要到启动时才暴露。

所以桌面版只做两件事：**查看真实运行状态**，以及**编辑配置、在应用前发现错误**。

## 2. 约束

| 约束 | 来源 |
|---|---|
| 网关可在无显示器的边缘设备上无头运行，二进制保持纯 Go | 现有交付方式 |
| 网关内核只有一份，桌面版不另写转发逻辑 | 测试与维护成本 |
| 工业现场常离线 | 部署环境；不能依赖 CDN、在线字体或另装运行时 |
| `config.yaml` 是权威产物，会被手工编辑、纳入版本控制 | 产品立场；图形编辑不能破坏注释和未展示字段，也不能覆盖他人的修改 |
| 不启用管理功能时，命令行版行为与此前完全一致 | 存量部署 |

## 3. 从约束推导出的设计决定

| # | 决定 | 理由 |
|---|---|---|
| D1 | 桌面框架用 Gio，作为独立 Go 模块 `desktop-native/` | 不需要 WebView 或额外运行时，单个可执行文件即可离线运行；GUI 依赖不进入根模块，网关仍可无头构建 |
| D2 | 网关以**子进程**运行：同一可执行文件带 `--sidecar` 启动自身，执行与命令行版相同的 `internal/cli` | 界面渲染与 GC 不与转发共用运行时；网关崩溃时界面保留并显示原因；应用配置就是重启子进程；界面与网关版本始终一致 |
| D3 | 管理 API 只读，默认关闭；配置只通过桌面端的本地文件模块修改 | 网关不暴露任何写入面；配置的权威来源始终是磁盘文件 |
| D4 | 草稿、已保存配置、运行配置三者分开维护 | 保存不等于生效；转发中断必须是用户确认后的显式动作 |
| D5 | 只展示真实证据 | 不伪造线路帧，设备值只取自成功的读取，缺失数据明确标出原因，不用零值冒充 |

**放弃的方案。** 起草时曾选择“网关内嵌浏览器控制台（含配置写回 HTTP 接口）＋ Electron 桌面外壳”，并已实现，于 2026-10-04 全部移除。当时记录在案的代价是：Electron 安装包约 130–140 MB、需要 Node 工具链和持续跟进 Chromium 安全更新；浏览器控制台要求网关提供配置写入接口。Wails、Tauri、浏览器 `--app` 模式在起草阶段即因 CGO/WebView2 依赖、Rust 工具链、依赖本机浏览器而未采用。

## 4. 目标与非目标

**目标：** 在 macOS、Windows、Linux（amd64、arm64）上，离线查看拓扑、请求与寄存器；可视化或以 YAML 编辑配置，校验结果与命令行版一致；安全地保存和应用配置；查看运行日志。

**非目标：** 配置热加载；多用户与权限；管理其他机器上的网关（桌面版只管理自己启动的子进程）；改变转发或路由语义；深色模式。

## 5. 产品行为

### 5.1 子进程与管理 API

- 启动参数为 `--sidecar -config <path> -ui-listen 127.0.0.1:0 -exit-on-stdin-eof -log-json-stderr`。子进程绑定回环地址的随机端口，通过 stdout 输出一行 `{"event":"ui_ready","addr":...}` 告知实际地址。
- 每次启动生成新的随机令牌，经 `MODMUX_UI_TOKEN` 传入；所有管理请求必须携带该 Bearer token，并通过 loopback Host 检查。
- 父进程关闭 stdin 即触发子进程优雅退出并刷写持久化；父进程崩溃时管道断开，效果相同。该模式下忽略 SIGPIPE，避免输出管道关闭时打断退出过程。
- 界面只使用三个只读端点：`/api/v1/status`（模型状态、各上游的启动/监听/失败/停止状态）、`/api/v1/events`（每个请求的请求与响应 PDU、耗时）、`/api/v1/simulations/<name>/registers`。数据由后台缓存，界面不在每帧发起网络请求。

### 5.2 配置工作台

- **两种编辑方式：** v1 可视化编辑（保留注释和未进入表单的字段，格式可能重排）与 YAML 原文编辑；v0 只能原文编辑，不自动升级。
- **校验：** 与命令行版使用同一套校验规则，包括启动时才检查的路由冲突，逐项定位到字段。
- **编辑事务：** 新增、复制、删除、批量修改、移动下游；批量操作先预览，存在引用或路由冲突时拒绝整次操作；撤销/重做最多 100 步。删除模型必须先处理引用；删除配置不删除持久化数据。
- **保存：** 原子替换并保留文件权限；检测外部修改，冲突时进入三方对照页，不覆盖磁盘内容。未保存草稿自动写入配置旁的私有恢复文件，重新打开可恢复。
- **应用：** “保存并应用”在确认后重启整个子进程：所有网关转发中断，所有 `memory` 模型清空。只有全部上游监听成功，才更新运行基线和本次会话的“最近健康配置”；失败时网关停止并显示原因，草稿保留，可手动运行最近健康配置（不覆盖已保存文件和草稿）。
- **默认文件：** 未指定 `-config` 时打开可执行文件旁（macOS 为 `ModMux.app` 旁）的 `config.yaml`；文件不存在则打开空白 v1 草稿，网关保持停止，首次保存不覆盖期间被其他程序创建的同名文件。相对持久化路径按配置文件目录解析。

### 5.3 联动监视

- 按网关、下游、Slave ID 组织拓扑与观测数据；选中请求可查看 PDU，并联动到相关寄存器。
- 请求历史保留最近 5000 条，每个网关最多 64 个主站入口；淘汰与遥测遗漏数量可见。
- 真实设备只显示最近一次成功读取的值，写入回显不覆盖读取结果；模拟模型的值从运行中的模型读取。数据缺失时区分无路由、进程内调用、无响应与未采集。

### 5.4 运行日志

- 汇集桌面与网关日志，可按级别、来源、网关、关键词筛选，支持暂停/跟随、复制与导出。
- 由桌面进程独立缓存（最多 5000 条、4 MiB，单条超过 16 KiB 截断），网关重启或管理连接中断后仍可查看；每次子进程启动有独立会话编号。不读取历史磁盘日志。

### 5.5 外观与分发

- 颜色、字号、圆角只来自 `desktop-native/design/tokens.json`，生成到代码；状态同时用文字、形状和颜色表达。
- Noto Sans SC 与 Go Mono 随应用打包，离线可用。
- 发布 macOS、Windows、Linux 的 amd64 与 arm64 包。Linux 构建需要 CGO 与图形开发包，Windows 不需要 CGO。

## 6. 已知限制

| 限制 | 说明 |
|---|---|
| 只采集 PDU | 不采集上下游 ADU、TCP 事务号、RTU CRC、分段耗时和上游异常回复；界面标为“未采集”，不重建 |
| 寄存器视图只显示地址 0–119 | 没有翻页或跳转到完整 0–65535 地址空间 |
| 不能从界面写模型 | 寄存器视图只读；写入只能通过 Modbus 业务入口或注入入口 |
| 应用配置是整体重启 | 不能只应用单个网关；`memory` 模型数据会清空 |
| 最近健康配置只在本次会话有效 | 重启桌面应用后不保留 |
| RTU `rqst_pause` 与 RS485/RTS 参数未被驱动使用 | 界面明确标注它们只保留在 YAML 中 |
| 下游状态点只表示最近一次请求结果 | 不代表实时连接状态 |
| 跨平台验证有限 | 交叉编译与离屏截图不能代替各系统实机的剪贴板、输入法和文件选择器验收 |

## 7. 验收依据

| 范围 | 方式 |
|---|---|
| 管理 API 默认关闭、令牌与 Host 校验、子进程启动/退出/父进程崩溃/事件流关闭 | `test/management_api_test.go`（真实网关进程） |
| 子进程流量、PDU、启动失败、重启、断连、崩溃与停止 | `desktop-native/internal/sidecar` 测试（真实子进程） |
| 布局、配置事务、运行基线、键盘、冲突、日志与运行状态 | `desktop-native/internal/workspace` 测试与离屏截图 |
| 设计令牌生成、颜色来源与对比度 | `desktop-native/design` 测试 |
| 命令行版默认行为不变、v0/v1 兼容 | 根模块 `go test ./...` 与 `test/` 端到端测试 |

验证命令见 [架构与验证](../../desktop-native/DEVELOPMENT.md#验证入口与范围)。

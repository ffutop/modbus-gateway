# PROTOTYPE · 配置工作台

当前原型已固化为 **config-A-v1（2026-10-05）**，作为正式优化的设计参照。设计决策与实施边界见 baseline/BASELINE.md。它仍是用于推演交互的可丢弃浏览器原型，参考本地 tracker 中的 desktop-native 配置 PRD。它靠近 Gio 模块，但不属于发布产物，也不替代原生实现。

在仓库根目录运行一个命令：

```sh
python3 desktop-native/prototype-config/serve.py
```

打开 http://127.0.0.1:8766/?variant=A 。端口冲突时加 `--port 8767`。需要 Python 3，不需安装前端依赖；用 Ctrl+C 停止。样式读取固化时从原生设计令牌导出的 baseline/tokens.json 快照，防止正式优化令牌后改变参考画面；该快照只作基线，不是新的设计令牌来源。字体复用仓库现有资源，其校验值记入 baseline/manifest.json。

## 已选定结构

- `?variant=A`：树形检查器。可视化展示对象树，YAML 隐藏对象树并使用可用宽度；可选右侧双变更检查器。
- B/C 探索布局已移除，截图作为历史证据保留。

底部悬浮栏用于切换场景、查看内存状态与重置。底栏独立占 76px，不是产品工具栏；原型文件没有纳入原生生产构建。

## 建议体验路径

1. 在底栏选择“运行 A → 已存 B → 草稿 C”。温控器波特率依次为 19200、38400、57600。分别打开待保存和待应用摘要，检查比较对象。
2. 点击“仅保存”，再点击“应用已保存配置”。取消确认后文件仍待应用；再次确认后全部配置同步。
3. 切换“路由冲突”，点击“修复问题”，定位从站 ID 字段；改为 10 后保存。
4. 打开温控器，输入自定义波特率，调整帧格式并展开 RS485；失焦时输入进入草稿。撤销/重做可回退字段事务。
5. 打开模拟模型，改名后观察关联事务的完成/放弃入口，查看使用方。
6. 总览选择对象后体验复制/删除预览。复制网关留空监听地址，必须补全后才可保存。
7. 切换“外部修改”，查看三个版本，保留草稿并更新基线后检查差异。此原型用字段表单演示手动合并，不做自动合并。
8. 切换“应用失败”恢复最近成功配置，或在应用确认中选择监听失败结果。已保存文件和草稿不随恢复覆盖。
9. 使用“状态”查看完整 draft/saved/running/disk 与两组差异。

新建入口：左侧网关/模拟模型分组加号，以及对应总览的具名按钮。网关先输入名称，再在详情添加上下游。模型可选择持久化类型；local/injector 的模型字段旁支持“新建并引用模型”，确认后返回原下游，取消无副作用，创建与绑定可一并撤销。YAML 隐藏结构化新建入口。

## 原型边界

- 所有数据和运行结果均在内存中模拟；刷新会重置，不调用真实设备、管理 API、子进程，也不写配置/恢复文件。
- YAML 是只读的关键配置投影，不是可导入、完整导出的配置编辑器。未实现生产 YAML 解析、注释保留、v0 编辑和磁盘文件合并。这些依然是 PRD 的正式实现要求。
- 路由、地址、串口和映射使用简化校验，只回答交互问题，不替代核心 Go 校验；没有验证硬件支持、持久化、跨平台可达性或大工程性能。
- 批量编辑、逐条迁移模型引用和完整 RTS 参数未扩展；当前覆盖复制、下游移动、删除及引用级联的代表操作。
- 不加入自动化测试或生产抽象。已用临时浏览器脚本检查代表流程，并查看两个尺寸的截图；截图位于 evidence。
- 方案已选定且淘汰布局已移除；保留本原型至正式实现完成验收。按正式工程标准重写原生实现，不直接移植脚本。验收后保留设计决策与最终证据，再删除或归档可执行原型。

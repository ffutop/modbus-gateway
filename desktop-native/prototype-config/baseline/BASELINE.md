# config-A-v1 · 可视化配置设计基线

固化日期：2026-10-05。状态：用户已选择 A 并要求固化，下一阶段为正式 Gio 优化。本文件定义已确认的布局和交互；完整功能范围及验收以仓库本地 tracker 中的配置 PRD 为准。

## 已确认设计

1. 使用 A 树形检查器：对象树、详情、按需打开的双变更检查器。淘汰 B/C 布局。
2. 可视化显示对象树；YAML 隐藏对象树，文本区占满标题下方剩余高度，长内容内部滚动。切回可视化保留选择和草稿。
3. 移除顶部泛化新建。网关与模型分组加号、各自总览具名入口共用对应流程；YAML 不展示结构化新建。
4. 网关先命名，创建后进入详情，分别添加上下游，不默认构造 TCP 设备；不完整配置保留草稿。
5. 独立模型可选择持久化；local/injector 支持新建并引用，确认原子创建与绑定并返回下游，取消不修改，撤销同时恢复模型和引用。
6. 树行使用展开位 12px、图标 16px、名称、状态四列，列间距 6px，每层缩进 20px。叶节点保留展开位。
7. 模型总览为可展开父节点，具体模型缩进一层，与上下游子节点对齐。网关展开与对象选择分开。
8. 上游 SVG 为 →□—，下游为 —□→，两者沿左到右表达方向；模型为层叠数据，网关为路由设备，全局运行设置为调节滑杆。按对象角色分配图标，local/injector 均属下游。颜色继承现有令牌，名称与角色提示保留。
9. 分别比较 draft↔saved 和 saved↔running。仅保存、确认应用、启动结果是三个阶段；取消应用保留已保存文件。
10. 实际应用重启整个子进程：全部网关转发中断、所有 memory 模型清空，不能以单个对象变化范围替代实际影响。

## 正式实现边界

原型验证了结构和代表性交互，没有实现完整配置编辑器。生产实现必须复用核心配置解析校验、配置文件原子保存、草稿恢复、Runtime/sidecar 边界，保持 Go 版本、v0/v1 兼容与既有功能。

尤其不能带入：只读且不完整的 YAML 投影、JS 简化校验、模拟启动结果、无磁盘的冲突处理，以及未完成的批量编辑、模型引用迁移、RS485 参数和性能验证。设计令牌仍只有原生 tokens.json 一处；SVG 可转换成等价 Gio 矢量路径。

建议实施顺序：布局与树图标 → 创建流程和必要参数 → 三份配置及保存应用状态 → 冲突/恢复和完整 YAML → 回归验收。每步保留既有未提交工作的有效能力，不整体覆盖工作区。

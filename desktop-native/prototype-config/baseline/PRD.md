# desktop-native 可视化配置工作台：补全操作闭环与精简交互

Status: ready-for-agent
Date: 2026-10-05
Scope: Gio 原生桌面版配置编辑；本文件是需求，尚未实施。

## Problem Statement

现场工程师需要快速配置多个网关，理解主站入口、Slave ID 路由、真实设备与共享模拟模型之间的关系，并在不中断现有通信的情况下核对变更。当前实现已有较完整的编辑能力，但功能入口、编辑提交和运行生效的层级不够清晰。用户容易遇到“已保存但没有生效”“高级选项隐藏了必要串口设置”“看到配置有问题，却不知道应先修哪里”等情况。

本次审查以当前工作区为基线，包含未提交的配置工作台实现，不把这些已有功能重新列为待新增。已有搜索筛选、引用跳转、新建引导、增删复制移动、批量预览、映射编辑、100 次事务撤销重做、私有草稿恢复、原子保存、外部版本冲突检查、重启确认和会话内最近成功配置恢复。这些能力应保留并回归验证。

源码与 1440×900、1100×680 原生截图共同支持以下问题：

| 发现 | 对用户的影响 | 需求决策 |
| --- | --- | --- |
| 页面级保存、搜索、返回、历史、筛选和对象级操作分散在多行工具栏 | 最小窗口下表单可用高度减少，主操作不明确 | 合并动作层级；保持上下文操作靠近对象 |
| 没有活动编辑时，仍显示主样式“完成编辑”和“放弃本次编辑” | 用户被迫判断额外提交层是否必要 | 仅活动事务显示提交与取消 |
| 总览未选择对象也展示复制、批量修改、移动下游、删除 | 用户看到与当前选择不匹配的动作 | 选择后显示适用的上下文动作 |
| 串口数据位、校验位、停止位、超时均标为高级 | 首次配置可能使用不匹配的帧格式 | 基础串口参数直接展示；RS485 专用设置按需展开 |
| 波特率只提供四个固定选项 | 合法的其他波特率无法在可视化表单输入 | 可编辑组合输入，保留常用值建议 |
| 桌面 sidecar 强制覆盖管理 API 地址，但全局页展示普通启停开关 | 用户以为它改变桌面管理连接 | 放入“命令行运行设置”，说明桌面覆盖行为 |
| “保存并应用”以未保存变更作为启用条件 | 已保存待生效时必须寻找另一处重启入口 | 配置页随状态提供保存并应用、应用已保存配置或启动 |
| 待生效摘要通过替换比较基线计算当前草稿变化 | 保存后再次编辑可能混入尚未保存内容 | 明确草稿对文件、文件对运行两个独立比较 |
| 影响摘要可列单个网关，但应用通过重启整个子进程实现 | 用户低估通信中断和 memory 数据清空范围 | 分开说明内容变化范围与实际重启范围 |
| 外部文件冲突提示要求重新打开应用后合并 | 草稿虽保留，恢复操作仍不闭环 | 页面内检查磁盘版本、对比与重新基准化 |
| 对象状态使用单一优先级文字和点 | 同时存在错误、未保存、待生效时信息容易被遮蔽 | 分开展示问题状态与变更状态 |

后四项中的行为问题来自源码审查，需按下述验收场景确认，不能把静态截图当作动态交互通过的证明。

## Solution

保留专业工具式的“对象导航—详情编辑—按需检查变更”结构，围绕“找到对象、完成配置、核对影响、保存、明确应用结果”组织工作台。默认进入网关总览；需要修复启动失败或恢复草稿时优先显示对应任务。

新增能力限于消除真实操作断点：路由覆盖与冲突解释、可输入任意合法波特率、外部变更对比与手动合并、清晰的运行应用状态、键盘操作及字段级错误定位。优化已有功能的可发现性和一致性，移除重复入口、无效动作和误导性表达。继续使用现有设计令牌，不重做品牌或引入网页外壳。

## User Stories

2. As a 新用户, I want 从空配置开始创建可运行网关, so that 我不必先写 YAML。
3. As a 熟练用户, I want 跳过新建引导并直接编辑对象, so that 重复任务不会被向导拖慢。
4. As a 配置维护者, I want 看到当前文件的实际名称、路径与版本, so that 我知道修改的是哪份工程。
5. As a 现场工程师, I want 按网关、协议、地址、串口和 Slave ID 搜索, so that 我能找到目标链路。
6. As a 配置维护者, I want 搜索字段中文名及 YAML 键名, so that 我能找到不熟悉的设置。
7. As a 配置维护者, I want 筛选有问题、未保存和待生效对象, so that 我能集中处理当前任务。
8. As a 现场工程师, I want 从匹配结果看到所属网关与匹配原因, so that 同名或同协议对象不会混淆。
9. As a 现场工程师, I want 返回后保留选择和滚动位置, so that 引用跳转不会打断工作。
10. As a 配置维护者, I want 同时看到错误和变更状态, so that 一个状态不会隐藏另一个。
11. As a 现场工程师, I want 区分上游监听地址和下游连接地址, so that 我不会把本地监听与远端设备混填。

13. As a 现场工程师, I want 输入串口设备路径并配置完整帧格式, so that 连接符合真实设备要求。

17. As a 配置维护者, I want 切换协议时明确知道哪些值被保留、忽略或清理, so that 旧参数不会悄悄生效。

19. As a 配置维护者, I want 路由冲突指明冲突 ID 和双方下游, so that 我能直接修复。

## Implementation Decisions

### 1. 交付范围与优先级

- P0：独立比较三份配置；准确的运行状态与应用范围；已保存配置应用入口；协议切换保真；必要串口参数；错误定位；YAML 往返与原子保存不退化。
- P1：工具栏精简、上下文批量动作、可编辑波特率、路由摘要、字段搜索、键盘路径、外部修改页面内合并。
- P2：大工程性能与辅助说明完善。P0 与 P1 为本 PRD 必需交付，不能仅完成视觉改动就标记完成。
- 沿用配置工作台、配置解析校验、路由解析、配置文件保存、草稿恢复、Runtime 与 sidecar 等现有模块。具体实现需先检查工作区已有能力，避免重复建设。

### 2. 信息结构与视觉减法

- 固定页面头包含真实文件名、可查看完整路径、模式切换、保存/运行状态及一个页面主动作；禁止固定写成 config.yaml。
- 用户已选定 A 树形检查器：可视化模式展示左侧对象树，YAML 模式隐藏对象树并将可用宽度留给文本；右侧变更检查器按需打开。切回可视化保留对象选择与草稿。YAML 文本区占满标题下方的剩余高度，长内容在文本区内滚动。
- 移除顶部泛化“新建”。网关与模拟模型各在左侧分组标题提供有明确提示的加号，总览提供具名创建按钮，共用对应创建流程。YAML 隐藏结构化创建入口。空状态按对象类型提供一致的创建文案。
- 新网关先命名创建，进入详情后添加上游和下游，不预设 TCP 设备；不完整对象保留为草稿。独立模型可输入名称、选择持久化。local/injector 的模型字段旁提供“新建并引用模型”，创建与绑定原子提交，返回原下游，取消不创建对象或更改引用。
- 搜索筛选归为一组；导航返回和历史动作归为一组。1100×680 下头部必须给主体留下至少 400dp 的可用高度（100% 密度）；不缩小字号挤入更多按钮。
- 默认网关总览；常规与模拟模型为独立导航组。上游与下游总览作为查询视图，避免与网关子节点形成难辨的重复树分支。
- 总览采用紧凑可扫描行，统一列出名称、所属网关、协议、端点/模型、Slave ID、问题/变更状态；长值可复制并查看全文。
- 未选择对象时隐藏批量操作；选中后显示数量与适用动作。纯网关选择不展示“移动下游”。切换筛选保留选择时必须提示隐藏选择数量；预览以真实全体选择为准。
- 无活动事务隐藏“完成编辑/放弃本次编辑”；撤销、重做、返回在无对应历史时禁用。删除类动作放入对象操作区；移除常驻大面积警告和重复说明。
- 保留“无引用”筛选但仅用于模型视图；无引用模型不是错误，不自动删除。问题筛选不因高级区折叠漏掉字段错误。
- 色彩、字号、圆角继续由设计令牌生成；状态配文字，不能仅用彩色点表示。
- 树中上游、下游、模拟模型使用统一线性矢量图标，上游按 →□—、下游按 —□→ 表达左到右流向，模型表示共享数据层叠结构；按角色而非协议分配图标，local/injector 同属下游。保留名称与角色提示，不能仅靠颜色区分；原生实现可使用等价 Gio 矢量路径。网关及模型总览为可展开父节点，具体模型和上下游缩进一层；保留展开位、图标、名称、状态四列，图标不会抵消层级缩进。全局运行设置提供同风格调节滑杆图标。

### 3. 编辑事务与协议参数

- 明确三个提交层级：输入到草稿、草稿保存到文件、已保存配置应用到子进程。普通字段失焦或切换对象时将合法输入合入草稿并形成事务；非法输入不丢弃，阻止会覆盖它的动作并指出原因。
- 模型改名、引用改绑、映射多字段修改采用显式事务，原子提交或取消。有活动事务时保存会先完成校验并提交该事务；不会要求用户再找一次“完成编辑”。
- 协议切换只在适用分组展示字段。适用性变化本身不得序列化零值覆盖未修改字段；保留后端认可的非活动字段，并说明它们当前不参与运行。若后端要求清理不适用字段，将清理与切换合成同一可撤销事务并预览，不能直接改变后端契约。
- RTU 基础组包含设备路径、波特率、数据位、校验位、停止位、超时、请求间隔。波特率为可编辑组合框，合法范围以核心与实际串口能力为准，常用值不是白名单。
- RS485 开关展开相应 RTS 延迟和电平等专用项；保留值、修改标记与错误数量在折叠时仍可发现。实际平台支持不足时说明限制，不假装参数已生效。
- 基础协议与持久化选项提供短中文说明，保留 tcp、rtu、rtu-over-tcp、local、injector 等契约标识。sql 当前是 sqlite3 存储，不新增数据库驱动选择或服务器凭证输入。
- 持久化路径显示与实际子进程一致的工作目录和解析路径；不把路径解释成相对应用可执行文件。删除、复制、改名均不擅自搬迁或删除数据文件。
- 管理 API 与 pprof 进入高级运行设置；管理 API 明示仅作用于直接 CLI 运行，桌面管理连接由 sidecar 覆盖。移除其作为桌面连接开关的表达，保留 YAML 字段兼容性。

### 4. 路由与映射解释

- 复用核心路由解析与校验：可视化预览显示规范化 Slave ID 集合与覆盖数量；错误显示冲突 ID、所属网关、双方下游及跳转入口。
- ID 有效范围遵循当前解析器 0–255，不因常见设备手册使用 1–247 就擅自收紧既有配置。local/injector 单 ID、空默认路由等规则沿用核心契约。
- 网关详情提供紧凑路由列表：ID→下游→真实端点/模型。默认路由单列说明；不新增第二套可拖拽拓扑编辑器。
- injector 映射展示源表、起始地址、数量、推导结束地址、目标表及目标区间。采用零基地址，说明与 4xxxx 等设备手册编号的区别，不自动猜测转换。
- 根据合法源/目标表组合约束选项；数量为正、区间越界、源重叠及共享模型目标重叠用核心校验判定。冲突信息包含关联模型与另一注入入口，关联编辑全部通过才提交。
- 不把配置映射编辑混入运行寄存器写入，也不在配置页生成测试流量。

### 5. 三份配置、保存与应用

- 分别保存 draft、saved、running 的内容与身份映射。草稿变更只比较 draft↔saved；待生效变更只比较 saved↔running；禁止借用草稿对象计算运行差异。
- 变更检查器提供“待保存”“待应用”两个视图，二者可同时有内容。注释/格式变化标为文本变化，不能凭字节不同声称路由发生变化；语义一致时显式说明无需运行变更。
- 比较示例必须成立：A 正在运行→保存 B→编辑未保存 C，此时待保存是 B→C，待应用是 A→B。取消 C 不影响待应用 B。
- 主动作状态：有效未保存变更为“保存并应用”，同时提供次级“仅保存”；已保存且存在运行语义差异为“应用已保存配置”；停止且已有有效配置为“启动网关”；启动/应用中禁用重复提交并显示进度。
- 保存成功、应用确认、应用成功是不同结果。保存后取消重启，文件保留为待生效；应用失败显示失败原因、最后日志及修复/最近成功配置恢复入口。
- 内容影响可按网关列出，但实际应用必须注明“整个网关进程重启，全部网关转发中断，全部运行中的 memory 模型数据清空”。改变一个网关不承诺局部热更新。
- 全部监听成功后才更新 running 基线及最近成功快照。运行最近成功快照后，已保存文件和草稿保留，状态明确表明运行的是恢复配置。
- 进程停止、启动失败、管理连接中断不显示“运行配置”健康徽标，仅根据文本一致判断已同步也是不够的。
- 配置保存继续使用全量核心校验、版本检查、原子替换、权限与符号链接保留。桌面“完整性要求”与核心合法性分别报告；不额外强制命名等 UI 习惯而阻断已由 CLI 支持的配置保存。新建引导可推荐命名，对缺名对象提供显示标签。

### 6. 外部冲突、恢复与 YAML

- 冲突页展示编辑基线、当前磁盘、当前草稿；允许复制/导出草稿、查看文本差异、将最新磁盘作为基线后在 YAML 手动合并。不得直接强制覆盖外部变更，也不实现未经设计的自动三方合并。
- 重新基准化必须保留草稿，明确需要再次校验和保存；保存前重新检查最新磁盘版本，第二次外部修改仍拒绝覆盖。单纯查看外部文件不修改 saved/running 基线。
- 原文 YAML 模式保存原文；可视化模式保留未修改注释与后端认可但未进入表单的高级字段，允许格式重排。v1 未知字段仍按核心契约拒绝，不能把“保留高级字段”解释为接受未知字段。
- v0 只提供原文编辑和清楚的版本说明，不自动迁移。语法非法时保留 YAML 输入与行列错误；切换模式不得 silently 丢失未提交数字或名称输入。
- 草稿恢复沿用私有恢复文件、写入去抖、清除队列失效与磁盘版本检测。外部冲突恢复引导进入同一合并流程，不要求重启应用。

### 7. 交互可达性与规模

- Cmd/Ctrl+S 保存，Cmd/Ctrl+F 聚焦搜索；撤销重做遵循平台习惯。文本编辑器拥有焦点时，文本撤销优先，不能同时撤销结构事务。
- Tab/Shift+Tab 顺序稳定；弹窗锁定焦点，Esc 取消；关闭弹窗恢复触发控件焦点。删除/重启确认期间所有背景点击、快捷键和批量命令暂停。
- 保存不可用时给出具体原因和修复入口，不能只有灰按钮；错误摘要按对象分组，点击后展开、滚动并聚焦目标字段。
- 1100×680 和 1440×900 验收；长中文、IPv6、长设备路径与长模型名不会覆盖操作。使用局部列表/表单滚动，保持主要状态和应用动作可见。
- 规模场景使用 100 个网关、1000 个下游、200 个模型及 2000 条映射；性能记录包含机器信息与操作耗时。目标：搜索/筛选到可见结果 p95≤200ms，常规编辑不在每个渲染帧重算全局引用/差异；性能失败需定位后优化，不能靠删功能达标。

## Testing Decisions

- 优先复用现有 workspace 交互驱动边界，测试用户动作到可观察草稿、错误、保存内容和 Runtime 调用；不测试私有字段排列、组件调用次数或实现函数拆分。
- 现有结构、工作台与 Runtime 测试已经覆盖身份保持、关联改名、事务历史、批量原子性、恢复和运行控制。新增场景沿用这些设施，不引入另一套业务状态机或 UI 专属配置解析器。
- 必须验证 A运行→B保存→C未保存的双差异；仅注释变化；停止但文件一致；已保存待应用；确认取消；启动失败；最近成功快照恢复；应用中重复点击。
- 参数验证覆盖自定义波特率、完整串口帧格式、RS485 折叠错误、协议往返、默认值与显式值区别、隐藏字段/注释保留、v0 原文及 v1 未知字段拒绝。
- 路由与映射覆盖核心合法边界、默认路由、重叠 ID、空/越界区间、共享模型跨网关注入冲突；错误必须可以定位相关对象。
- configfile 边界测试磁盘外部修改、重新基准化、再次外部修改、权限/写入错误、符号链接以及失败不丢草稿；恢复测试保留非法中间输入及清除后排队写入不复活。
- workspace 输入驱动测试键盘焦点、Enter/Esc、弹窗背景隔离、无活动事务动作与混合批量选择；渲染快照覆盖上述状态和两个窗口尺寸，人工看图确认裁切与层级。截图生成通过不等于交互通过。
- 复用 Runtime/sidecar 的启停契约测试；若实现触及进程启动，补真实 sidecar 测试并按项目约定运行独立 E2E 模块。缺 socat 或运行权限时写明未验证项。
- 所需检查：根模块配置/路由回归与 Go 1.21 兼容；desktop-native 测试；设计令牌生成一致性、裸色与对比度守卫。仅格式化修改文件。

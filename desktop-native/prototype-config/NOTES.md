# 原型问题与结论

## 要回答的问题

在多网关工程中，哪种结构最能帮助现场工程师找到配置、理解草稿/文件/运行状态，并完成保存和应用？比较 A 树形检查器、B 表格工作台、C 步骤式配置，同时允许组合各方案的有效部分。

## 已确认决策

用户已选择 A 树形检查器作为配置工作台。可视化模式展示左侧对象树；YAML 模式隐藏对象树，文本区域使用可用宽度，右侧变更检查器仍可按需打开。切回可视化保留所选对象与草稿状态。YAML 文本区填满标题下方剩余高度，长内容在文本区内滚动。

B/C 的交互布局和方案切换器已移除，原截图保留为探索记录。当前仍为可丢弃原型，后续原生实现应按正式工程标准重写。

新建入口已调整：移除顶部泛化“新建”；左侧网关与模型分组的加号具有明确名称，总览分别提供“新建网关”和“新建模拟模型”，共用对应流程。YAML 不显示结构化创建入口。

网关先命名创建，随后在详情添加上下游，不默认创建 TCP 设备。独立模型支持选择持久化类型。local/injector 可在模型字段旁“新建并引用模型”，确认时原子创建与绑定，返回原下游，一次撤销恢复两者；取消不留下对象。网关与模型空状态分别提供匹配的创建入口。

对象树改用同一笔画与网格的内联 SVG：上游用进入网关的箭头，下游用离开网关的箭头，模拟模型用共享数据层叠图形。三种图标用轮廓区分，不依赖颜色；local/injector 仍属于下游，不使用模型图标替代其路由角色。图标旁保留名称，并通过悬停提示与可访问名称明确角色。图标颜色继承现有设计令牌。

树排版使用固定“展开位 12px—图标 16px—名称—状态”列，列间距 6px，每层增加 20px 缩进。叶节点保留展开位，避免父网关的展开箭头抵消层级；模拟模型总览作为可展开父节点，具体模型增加一层 20px 缩进，与网关的上下游子节点对齐。按用户指定，上下游均沿左到右表达流向：上游为 →□—，下游为 —□→，箭头分别位于端点框左侧和右侧。网关展开控件与对象选择分离，点击箭头实际收起/展开，引用导航到子节点时展开父节点。

## 已推演的行为

- 运行 A、保存 B、编辑 C：待保存比较 B→C，待应用比较 A→B。
- 仅保存后取消应用：文件更新、运行不变，页面保留直接应用入口。
- 全进程重启影响单独说明，不以内容变化范围代替中断范围。
- 普通字段失焦进入草稿；模型改名使用关联事务。
- 外部冲突更新基线保留草稿；最近成功配置恢复不修改草稿或已保存文件。

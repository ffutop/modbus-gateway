# 原生桌面端开发进度

正式运行入口为 `go run . -config ../config.yaml`。界面基线来自 2026-10-04 的九轮原型评审；原型代码（`prototype-ui/`，模拟流量）已在落地后删除，可从 git 历史查看，结论汇总如下。

## 界面选型记录

1. **主线**：比较报文优先（三栏抓包）、设备工作台（对象树 + 寄存器网格）与双联视图后，选双联视图：报文与寄存器联动；先选链路再看请求；一次请求的上游（主站 ↔ 网关）与下游（网关 ↔ 设备）两段都要可见；模拟模型下游是进程内调用、没有线路帧，需专属表达。
2. **布局（C1 + C2 拓扑）**：左侧链路列表（网关 → 下游，模型单独汇总），右侧顶部是只画当前网关的拓扑（点击主站、下游或模型节点筛选，再点取消），下方是请求时序图与寄存器两栏。时序图为主站／网关／设备三条泳道；模型泳道为虚线，箭头写操作而非字节。
3. **配置编辑**：同一份草稿有“可视化／config.yaml”两种模式，校验使用真实 `ParseDraft` 与 `Problems`。原始模式保存原样写入；可视化修改保留注释与未进入表单的字段（格式可能重排）；原始文本无法解析时不能保存或切回可视化，可放弃文本修改。v0 只做原文编辑，不隐式升级。
4. **诊断语义（P0/P1）**：按 Slave ID 分开请求与寄存器；injector 显示“源表 @a → 目标表 @b ×n”并跳到目标范围；模型显示当前值，真实设备显示最近一次成功读取值，写入回显不当作读取确认；“本请求”列保留所选请求的历史值；缺失帧区分无路由、进程内调用、无响应与未采集；问题区可定位到对象、字段或 YAML 行。
5. **视觉**：颜色、字号、圆角、遮罩只来自 `design/tokens.json`（desktop-native 密度 1.04：正文 13sp、标签 11.5sp、等宽 12sp）；黑底白字只用于主要选择与网关节点，蓝色限于焦点、注入流与字段关联，状态同时用颜色、形状与文字表达。
6. **桌面框架**：顶部 28dp 菜单栏（文件／编辑／查看／网关）、40dp 模块工具栏（联动监视／配置编辑）、底部 24dp 状态栏；菜单由 Gio 在应用内绘制，尚无操作系统原生菜单与键盘菜单导航。
7. **文字**：单行文字统一行框与基线，不依赖字形包围框（`typography_test.go` 在 1／1.5／2 倍缩放下回归）；界面字体链 `Go, Noto Sans SC`，等宽 `Go Mono, Noto Sans SC`，Noto 常规／粗体随应用打包（约 16 MiB）。


## 第一批：真实监视与安全保存（2026-10-04）

已完成：

- 正式入口迁至 `internal/workspace`，保留菜单、工具栏、状态栏、token 与 Go／打包 Noto 字体链。
- 根据实际运行配置建立网关、下游、路由、模型拓扑；从 Recorder 取得请求和主站信息，不启动模拟发生器。
- 接入真实 local／injector 模型数据；设备最后成功读取值按 Slave ID 隔离，保留请求历史值，写入回显与失败不覆盖读取证据。
- 请求历史使用有界环形缓冲区；主站、控件和历史有界，缓冲区遗漏可见。
- 可视化／原文配置编辑接入真实文件保存，验证路由与模型规则，检测外部修改，保持文件权限、原文注释及 v0 版本；失败保留草稿和运行基线。
- 配置／模型装配失败可进入原文编辑器，错误持续可见；空配置与非法 YAML 不造成布局崩溃。

验证：真实 Modbus TCP 请求通过进程内网关验证 local 写入、injector 映射和读取；自动检查 Slave ID 隔离、历史淘汰、遥测遗漏、保存冲突、权限、符号链接、v0 原文及失败布局。截图覆盖 1440×900、1100×680 的联动、菜单、配置、YAML 与启动错误状态。系统剪贴板、输入法和跨平台实机不属于离屏截图验证范围。

## 第二批：子进程模式（2026-10-04）

Electron 外壳已移除，原生版是唯一的桌面实现。网关改为子进程（sidecar）运行，主要依据是故障隔离与配置生效；界面渲染与 GC 不再与转发共用运行时是附带收益（实测在 2 核限制、交互时 60 fps 下，进程内模式的转发 p99 约从 0.5 ms 升至 1.4 ms）。界面关闭时网关随之退出。

已完成：

- 同一可执行文件以 `--sidecar` 启动自身，运行根模块 `internal/cli`（命令行版入口），只分发一个文件。协议沿用 `-ui-listen 127.0.0.1:0`、stdout 的 `ui_ready` 行、`MODMUX_UI_TOKEN` 一次性令牌与 `-exit-on-stdin-eof`；Windows 下子进程不弹出控制台。
- `-exit-on-stdin-eof` 时网关忽略 SIGPIPE：此前父进程先退出会使网关在写关闭日志时被 SIGPIPE 终止，跳过持久化刷写（`test/management_api_test.go` 回归覆盖）。
- 管理 API 事件流带请求／响应 PDU（十六进制），`/api/v1/status` 提供各上游监听状态；上游在绑定端口或打开串口后报告就绪。
- 数据源接口 `internal/live`：`Source`（事件、寄存器窗口、监听状态）与 `Runtime`（进程阶段、重启）。正式运行使用 `sidecar.Supervisor`；`live.Local` 只用于测试与开发。
- 工具栏“重启网关”带中断与 memory 数据清空确认，有未保存修改或启动中时禁用；状态栏显示启动中／运行中（监听 n/m 或失败原因）／已停止（原因与最后几行输出）。重启或启动失败后按配置文件重建工作台。

验证：`internal/sidecar` 以测试二进制充当子进程，覆盖真实流量与 PDU、寄存器、监听成功与失败、重启换端口、启动失败输出、崩溃检测与恢复、优雅停止（含 `-race`）；工作台覆盖状态栏文字、重启确认与禁用条件，截图新增重启确认状态。实机验证了强制结束父进程后子进程退出。

## 第三批：界面每帧内存分配（2026-10-04）

原因：联动视图每帧调用两次 `World.Exchanges` 并再追加一次筛选结果，三次整段复制 5000 条请求历史（另有一份寄存器窗格从未使用的拷贝）。

已完成：

- `World` 增加历史版本号 `gen` 与不复制的遍历 `Each`；联动视图按“链路 + 表 + 寄存器 + 仅异常 + gen”缓存投影（指向历史的指针、读写计数），只在历史或筛选变化时重建，最多每 100 ms 一次。
- 删除寄存器窗格未使用的历史拷贝；`World.record` 的去重改为栈上小数组，不再每条请求分配 map。
- 重绘节奏：有请求到达后 2 秒内每 100 ms 轮询，空闲时 1 秒心跳；sidecar 客户端在新请求或监听状态变化时主动唤醒窗口。
- `BenchmarkWorkspaceFrame`（5000 条历史、1000 次/s）与 `TestBusyFrameStaysWithinAllocationBudget`（每帧不超过 200 KB，race 模式跳过）约束回退。

验证：布局基准每帧分配 10.0 MB → 55 KB，耗时 2.6 ms → 0.73 ms。复用延迟实验（GOMAXPROCS=2、进程内、60 fps 离屏 GPU 渲染、1000 次/s）：转发 p99 1.44 ms → 0.44 ms（无 UI 基线 0.49 ms），p99.9 2.61 ms → 0.64–0.76 ms；GC 274 次 → 14–15 次／22 秒；整进程每帧分配（含网关与 GPU 提交）7 MB → 318 KB；界面帧耗时 p99 11 ms → 5.2–9.9 ms，尚未稳定低于 8 ms，余量主要在 GPU 提交与文字排版。

## 后续批次及验收边界

1. **配置应用的回退**：新配置启动失败时可一键以上一次成功运行的配置文本恢复运行，恢复结果可见；不得覆盖用户已保存的新文件。
2. **完整报文采集**：在各 transport 的实际收发边界记录上下游 ADU 和单段时间，关联请求；覆盖 TCP 事务号、RTU CRC、RTU over TCP、无路由及异常回复。无帧与未采集需要明确区分，禁止由 PDU 补造线路帧。
3. **寄存器完整地址浏览与模型写入**：支持 0–65535 地址范围、跳转、分页及请求关联；模型写入走 Simulation 的写入／持久化／审计链路，真实设备观测值不得直接改写。
4. **桌面交互验收**：菜单快捷键与键盘导航、中文输入法、系统剪贴板、关闭前未保存草稿提醒、Windows/Linux 实机及持续高流量性能。

当前不是完整桌面版发布：暂不提供启动失败自动回退、真实四段 ADU、全地址寄存器浏览或人工模型写入。

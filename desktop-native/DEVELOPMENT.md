# 原生桌面端架构与验证

正式入口为 `go run . -config ../config.yaml`。本文件记录最终实现的设计决策与验证入口；完整功能及平台依赖见 [README.md](README.md)。

## 模块职责

根模块 `internal/cli` 是 CLI 和桌面子进程共用的命令入口；`internal/app` 装配模拟模型和网关。转发实现不依赖 Gio，桌面依赖留在独立 Go 模块内。

桌面 `internal/sidecar` 管理子进程、健康状态和管理接口缓存；`internal/live` 定义界面读取数据与控制运行的接口，`live.Local` 仅供测试和开发。`internal/configfile` 负责保存、外部修改检测和私有草稿恢复；`internal/workspace` 管理界面与编辑事务；`internal/runlog` 独立采集桌面及子进程日志。

## 运行与配置决策

- 同一可执行文件以 `--sidecar` 启动自身，调用根模块 `internal/cli`。使用动态 loopback 端口、stdout `ui_ready` 通知、每次启动独立的 `MODMUX_UI_TOKEN` 和 `-exit-on-stdin-eof` 管理生命周期。关闭窗口停止网关；该模式忽略 SIGPIPE，使父进程退出后仍能完成持久化刷新。
- 子进程隔离界面渲染与协议转发。界面通过后台缓存读取数据，不在每帧同步进行网络请求。管理接口只读取 status、events 和 registers。
- 配置文件是权威产物。草稿、磁盘内容和运行基线分别维护；保存不自动改变运行配置。只有全部监听器启动成功，才更新运行基线和本次会话的健康配置快照。
- 保存检测外部修改，失败保留草稿。v0 保持原文编辑，不隐式升级；v1 可视化编辑保留注释和未进入表单的字段，格式可能重排。批量操作先预览，冲突拒绝整次事务。
- 重启、恢复和删除需要明确的模态确认。删除模型须处理共享引用；删除配置不删除持久化数据。恢复最近健康配置不覆盖已保存文件和未保存草稿。
- 文件不存在时打开空白 v1 草稿，网关保持停止；首次保存不能覆盖同时被其他程序创建的文件。相对持久化路径按配置文件目录解析。

## 界面与诊断决策

- 左侧按网关和下游选择链路，右侧显示当前拓扑、请求时序和寄存器联动。进程内模型调用采用专用表达，不伪造线路帧。
- 按网关、下游和 Slave ID 隔离观测数据。真实设备只显示最近成功读取的值；写入回显不能替代读取证据。所选请求保留历史值，缺失数据区分无路由、进程内调用、无响应和未采集。
- 请求历史与日志有界，淘汰和遥测遗漏可见；请求投影随历史版本和筛选变化刷新，避免每帧复制全部历史。
- 颜色、字号、圆角和遮罩来自 `design/tokens.json`。界面字体使用打包的 Noto Sans SC，等宽值使用 Go Mono。状态同时通过文字、形状和颜色表达。
- 配置编辑采用分组导航、总览表格和双列表单；联动监视、配置编辑、运行日志共享菜单、工具栏和状态栏。菜单由 Gio 在应用内绘制。

## 验证入口与范围

```sh
go vet ./...
go test ./...
go generate ./design
WORKSPACE_SNAPSHOT_DIR=/tmp/modmux-workspace go test ./internal/workspace -run TestWorkspaceSnapshots -count=1
GOOS=windows go build -o /tmp/modmux-desktop.exe .
```

设计包测试校验令牌生成、颜色来源与对比度。工作台测试覆盖布局、配置事务、基线、键盘、冲突、日志和运行状态；sidecar 测试通过真实子进程覆盖流量、PDU、启动失败、重启、断连、崩溃和停止。根目录 `test/` 单独模块覆盖真实网关管理接口、虚拟串口及持久化。

离屏截图不验证系统剪贴板、输入法或平台文件选择器的实机交互。跨平台编译不等同于跨平台运行验证。根模块 RTU 测试存在既有时序竞争，CI 尚未全量启用 race 检测。

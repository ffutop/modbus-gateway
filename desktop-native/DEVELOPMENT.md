## 后续批次及验收边界

1. **启动确认和进程内配置应用**：为全部上游提供明确的就绪／失败反馈；应用配置在后台执行，确认前说明连接中断及模型影响。失败不得清除待应用差异；恢复旧运行配置的结果必须可见。共享 memory 模型、file/mmap 资源及存量连接的关闭与迁移需单独验证。目前禁止以固定等待时间推断启动成功。
2. **完整报文采集**：在各 transport 的实际收发边界记录上下游 ADU 和单段时间，关联请求；覆盖 TCP 事务号、RTU CRC、RTU over TCP、无路由及异常回复。无帧与未采集需要明确区分，禁止由 PDU 补造线路帧。
3. **寄存器完整地址浏览与模型写入**：支持 0–65535 地址范围、跳转、分页及请求关联；模型写入走 Simulation 的写入／持久化／审计链路，真实设备观测值不得直接改写。
4. **桌面交互验收**：菜单快捷键与键盘导航、中文输入法、系统剪贴板、关闭前未保存草稿提醒、Windows/Linux 实机及持续高流量性能。

第一批不是完整桌面版发布：暂不提供进程内重启、真实四段 ADU、全地址寄存器浏览或人工模型写入。
